## Dependency notes

- Plan 001 is intentionally one coordinated migration because the Node,
  package-manager, TypeScript, ESLint, Next.js, Prisma, and Serverless peer
  ranges overlap. Within the plan, each dependency wave has its own green
  verification gate and should be committed separately.
- As of 2026-08-07, Node 26 is a Current release rather than LTS, while AWS
  Lambda and Vercel expose Node 24 as their newest managed runtime. The plan
  adopts Node 26 for local development and CI compatibility, upgrades deployed
  runtimes from EOL Node 20 to Node 24, and defers production Node 26 until both
  hosting platforms support it.
- ESLint remains pinned to 9.39.2 by project decision and to preserve the
  currently supported peer range of the React ESLint plugins.
- `@types/node` remains on the Node 24 line so application types match the
  managed production runtime rather than the newer local and CI runtime.
- Prisma 7.9.1 generation, builds, and tests pass on Node 26, but its published
  runtime support does not yet list Node 26; production therefore remains on
  the supported Node 24 runtime.

## Findings considered and rejected

- Force Node 26 into AWS Lambda through a custom runtime or container: rejected
  because it adds runtime ownership and operational risk solely to get ahead of
  managed-platform support.
- Upgrade TypeScript directly to 7.0.2: deferred because
  `typescript-eslint@8.66.0` currently declares TypeScript `<6.1.0`.
- Keep Serverless Framework 3 indefinitely: rejected because v3 is unmaintained
  and the current lockfile audit traces several critical/high advisories through
  it; v4's authentication/license gate must be resolved instead.
